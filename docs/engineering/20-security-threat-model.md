## 1. Scope and assets

**Assets:** the user's project content (scripts, story, production data, media), Private Notes, the local profile,
integrity of exported documents, and the integrity of downloaded runtime, model and update binaries.

**Trust boundaries:**

```text
[ untrusted input files: imports, packages, media, URLs ]      [ untrusted network: model CDN (user-started download), update endpoint (planned) ]
                    │ user-chosen path                                       │ HTTPS + Ed25519 manifest + SHA-256
                    ▼                                                        ▼
[ WebView (React): untrusted renderer ] ──of_invoke──► [ Rust core: trusted ] ──► [ project folder / app data ]
                                                  │            │ loopback + per-launch key           │
                                                  │            ▼                                     ▼
                                                  │  [ llama.cpp chat + embedding sidecars:  [ cache/intelligence.sqlite:
                                                  │    untrusted output ]                        untrusted derived file ]
                                                  ▼
                                   [ model tool choices: untrusted; toolbox + Change Set boundary ]
```

AI-specific assets: the human approval boundary (only the user applies changes), other users' private notes, and the
rule that AI authority never exceeds the user's (AI specification §2, Security spec §16).

**Out of scope / removed:** real-time LAN collaboration was removed by product-owner decision (ADR-0007).
OpenFrame opens **no listening socket**, so network listener, discovery, pairing and session-authorization threats do
not apply. There are no accounts or servers, so credential theft and server compromise do not apply. Malware running
as the same Windows user is out of scope: it can read the user's files regardless (the Security spec relies on OS
account protection, and encryption at rest is later scope).

## 3. Secure storage

- **At rest:** project data is plain SQLite + files, protected by Windows account ACLs (the user profile). OpenFrame
  does **not** claim encryption (Security spec: "only claimed once implemented and tested"). Optional encrypted
  projects and packages are later scope and need their own ADR (key management, recovery).
- **Secrets:** the product as built today has none. No accounts, API keys or tokens are stored. The AI sidecar keys are ephemeral (one per
  launch, passed through the child's environment) and held in memory only.
- **Derived AI data:** `cache/intelligence.sqlite` inside the project folder holds derived chunks of permitted project
  text (no contact details), vectors and graph nodes. It is deletable at any time and rebuilt; it is not encrypted,
  like the project database itself. If a future feature needs a secret, it goes in Windows Credential Manager behind an adapter (ESD §14),
  never in SQLite or plain files.
- **Temporary files:** writes use temp siblings in the same folder (`*.tmp`, `*.partial`, `*.importing`), renamed
  atomically and removed on failure. Nothing is written to `%TEMP%` with content, except OS dialogs.
- **Deletion:** "delete" is recoverable. Permanent purge removes rows and, after commit, the managed files it
  exclusively owns. Project deletion goes to the Recycle Bin. No secure-erase claims are made.

   phase W5 on (ADR-0028); until then the deterministic checks in `ai_toolbox.rs` and `ai_agent.rs` stand.
6. **Package authenticity (PKG-04, PKG-05): accepted risk, recorded.** Packages stay unsigned by design (file-based
   collaboration, no accounts). The mitigations are in place: linked local files in a received package are never
   copied by a later export, archives are screened (`archive.rs`, fuzzed in W3), and schema screening refuses foreign
   triggers and views. Signed packages would need an ADR for key distribution; not planned in Chapter 1.
8. **Web view background traffic (T33, T24): found in W3, fix assigned to W4.** With a project open and no WebDriver,
   two WebView2 processes of the app held connections to Microsoft addresses (`2603:1046:c06:cc1::2`,
   `2620:1ec:33::11`) for 40 s. It is the WebView2 runtime's own background traffic, not OpenFrame code, and it breaks
   "no silent network use". Decision: W4 passes WebView2 arguments that switch off background networking and
   component updates (keeping wry's SmartScreen and menu defaults) and proves it with spec 05 on the release build.
   Spec 05 fails until then, on purpose.
7. **New surfaces of the 2026-10-15 decisions: assigned to the phases that build them.** T38 (graphics-card probe and
   runtime) is reviewed in W7, T39 (learned memory and the numbers-only AI log) in W5 and W6, and T40 (the Mac shell
   interface) in M2. Each phase's exit includes its threat review.

This review covered the code on `master` at `a31ee7f`. The summary is in [`SECURITY_REVIEW_2026-09-30.md`](../archive/2026-09-30-security-review.md).
