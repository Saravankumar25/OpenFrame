## Executive finding — current state

The repository has moved materially since the 2026-09-30 audit. The largest change is the Offline AI/agentic RAG implementation merged on 2026-10-01. The current README now explicitly classifies Offline AI and the AI assistant as **Implemented**, whereas the prior audit correctly classified the same eight AI-related manual rows as source-complete but not shippable under the then-current release declaration. The current AI implementation now includes a managed Gemma 3 1B Instruct local runtime, BGE small English embeddings, hybrid retrieval, a universal bounded toolbox, provenance/context assembly, and human-only Change Set application.

The repository is still **pre-release**. The README continues to mark the creative and production workspaces — Idea Vault, Story Board, Screenplay, Breakdown/Catalog/Locations/Cast/Crew, visual planning, Schedule/Call Sheets/Sides/Reports, and import/export/backup package workflows — as **In development / not usable in this build**. The source tree is therefore substantially ahead of the declared release state, but the product is not yet end-to-end shippable.

The correct interpretation is not “stop everything until the old manual list is finished.” Many new-spec items are direct deepenings of those same modules. The safest path is to build a **superset contract first** for each module and then implement missing manual behavior plus new-spec behavior together, while running orthogonal work (themes, AI evaluation, release hardening, fixture generation) in parallel and behind clean interfaces.

## Cross-cutting gaps and mismatches that explain the remaining work

### 1. The repository has a two-level “done” problem

There are now two materially different notions of completion: source implementation and release-ready behavior. The repository uses “In development” to mean the module is being built against the foundation but is not usable in the current build. Therefore a source audit alone will overestimate product completeness.

The execution plan must keep these states separate: **specified → modeled → backend implemented → IPC reachable → UI reachable → persistence/undo/recovery validated → export/re-import validated → AI integrated → E2E verified → release-ready**.

### 2. AI is no longer a separate future subsystem; it is now part of the architecture

The 2026-10-01 commit changed this materially. `openframe-ai` owns runtime/model lifecycle, `openframe-search` owns the derived retrieval primitives, the application AI module owns tool catalogs/orchestration/change sets/context assembly, and the desktop layer owns conversation/proposal/setup UI. The safe implication is: **do not build future features and “add AI later.”** Add AI metadata, read/proposal tools, indexing hooks and evaluation fixtures as each new canonical feature lands.

### 3. New-spec items should be reconciled with the existing manual, not treated as a second product

The revised specification deliberately deepens the same product surface: professional screenplay pagination, continuation, scene numbers, title page, custom elements, FDX round-trip, Story Board card display, Breakdown efficiency, Schedule timing/travel/availability, DOOD, richer Call Sheets, Planned/Actual budget, templates, multilingual support, and theme customization. Implementing the manual’s minimal version first and then rewriting it for the new specification would create unnecessary schema churn, duplicated UI states, duplicate tests, and AI tool churn.

### 4. Project Home still has a concrete reachability mismatch

The current `NewProjectHome` still exposes Idea Vault, Build Story, and Write/Import Screenplay as the prominent starting actions. A direct shoot-planning route is still not presented there even though Breakdown/Production are available elsewhere. `ActiveProjectHome` similarly remains narrower than the richer production summary described in the baseline audit. These are reachability/UX gaps, not missing backend architecture.

### 5. The theme system is a genuinely new, orthogonal feature

The revised 47A specification is not yet represented in the current tree. The current UI has a tokenized-looking palette, but `openframe.css` explicitly calls itself a prototype and the live settings workspace has no Appearance route. The correct implementation is an app-level appearance layer that changes semantic UI tokens only; it must not change screenplay document rendering, production semantics, project data, permissions, shortcuts or exports.

### 6. Current documentation has at least two stale pockets

`OpenFrame_ESD_Technical_Architecture.md` still describes older LAN-oriented architecture that is superseded by ADR-0007. `DEVELOPMENT.md` also contains a statement that later crates such as `openframe-search`, `openframe-import-export`, and `openframe-ai` were not yet created, while the current tree clearly contains those crates. These must be reconciled before implementation accelerates so an agent does not follow obsolete instructions.

### 7. LAN-removal cleanup remains necessary

ADR-0007 removed real-time LAN collaboration, but the prior audit noted leftover capability/origin/wording traces such as `Capability::{HostSession, JoinSession}`, `ActorOrigin::Lan`, LAN activity-origin values, and network-location messaging. Before final release, remove or quarantine dead LAN semantics so the remaining Exchange/Review/Response package workflow is the only collaboration model represented in active code/docs.

### 8. Installer/license/release gates are still external blockers

The README still says no installer has been published and the signed installer/updater pipeline is blocked on certificate, updater key, and license selection. No amount of feature completion alone makes the product release-complete until these gates are closed.

## Current repository architecture that should be protected

| Layer | Current role | Protect this boundary |
|---|---|---|
| React desktop | Presentation, route/state, user interaction | Never write SQLite/files/network directly |
| `of_invoke` typed IPC | Single UI→Rust command boundary | Keep allow-listing and generated DTOs authoritative |
| `Registry` | Query/command allow-list and operation metadata | Every canonical operation must register once |
| `Store::mutate` | Transaction + undo + activity + reindex + events + save-state pipeline | Do not create side write paths |
| Domain | identities, capabilities, enums, validation contracts | Keep I/O out |
| Project SQLite | Canonical project truth | Never let AI/search/theme caches become canonical |
| Project filesystem/assets | Managed files/media | Route by validated Rust identifiers, not UI paths |
| `openframe-search` | Derived FTS/vector/graph retrieval primitives | Derived/rebuildable; never authoritative |
| `openframe-ai` | Optional local model/runtime/embedding lifecycle | Remains optional; failure must not block core editing |
| AI toolbox + Change Set | AI read/proposal layer | AI may propose; local human applies via ordinary commands |
| File packages | File-based collaboration/import/export boundary | Validate → preview → explicit human apply |

## What is genuinely implemented now

According to the current repository declaration and inspected source: project lifecycle, single-writer locking/UNC refusal, continuous autosave, save checkpoints/status, crash recovery, safe schema migration, generic undo/redo, Recently Deleted, Activity history, Project Files, app shell/Home/navigation/search/toasts, plus Offline AI installation/runtime management and the AI assistant/toolbox/hybrid retrieval/Change Set workflow.

## What remains not release-ready now

The creative and production workspaces are still explicitly marked In development: Idea Vault, Story Board, Screenplay, Breakdown/Catalog/Locations/Cast/Crew, Moodboards/Storyboards/Shot Lists, Schedule/Call Sheets/Sides/Reports, and the broader interchange/backup package surface. In addition, the revised new-spec features around professional screenplay depth, theme customization, richer production timing, DOOD, richer call sheets, proofing and output regression still require implementation and/or release validation.

## What was deliberately removed

Real-time LAN collaboration — host/join, discovery, presence, live soft locks, live conflict workflow and disconnect handling — remains removed by ADR-0007 (2026-09-30). The intended collaboration model is file-based Exchange → Review → Response packages.

## Important audit limitations

1. This update is a **static repository/release-state audit**. It did not execute the Windows/Tauri application or drive all 181 figures as end-to-end UI scenarios.
2. The current GitHub repository’s binary user-manual files were modified in the latest commit, but the binary content was not page-diffable through the inspection interface. The supplied 181-row audit remains the figure-level baseline rather than a claim that every manual page remained textually identical.
3. “Implemented” is used according to current repository declarations plus concrete source evidence. It is not a guarantee that no runtime defect exists.
4. Exact “done” status for each revised-spec requirement must therefore be closed by the implementation/QA ledger described in the master completion plan, not by source-code presence alone.

## Bottom line — updated

OpenFrame is farther along than the previous audit suggested because the AI subsystem has now crossed from “source-complete but not shippable” to “implemented” by the repository’s own declaration. The remaining challenge is not to write the application from zero. It is to convert a large set of already-structured modules into a **single, coherent, release-ready vertical product**, while simultaneously deepening the same modules according to the 2026-10-02 revised specification.

The recommended execution model is therefore **parallel, dependency-aware, contract-first development**: merge manual completion and revised-spec additions where they touch the same domain; isolate orthogonal changes such as Appearance/Themes; integrate AI metadata/index/evals continuously; and make every feature prove the full lifecycle: **Discover → Use → Save → Undo → Recover → Export → Re-import/Reopen → Continue**, plus security, permission, performance and Windows E2E gates.
