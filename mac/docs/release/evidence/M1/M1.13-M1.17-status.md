### M1.17 (`specs/90-visual-baseline.test.mjs`, `lib/png.mjs`)
`lib/png.mjs` decodes, encodes and diffs PNGs using zlib only.

The spec's default mode compares each screen with the M0.20 baseline:
- **Tolerance:** a pixel differs when a channel is off by more than 24 of 255. A screen fails when more than 0.1 % of its pixels differ.
- **Ignore regions:** relative and wall-clock times, the App Home card preview, the per-run project path, and the transient toast band.
- **On failure:** writes diff PNGs to `tests/e2e/artifacts/visual/`.

Other modes:
- `E2E_UPDATE_BASELINE=1` regenerates the baseline.
- `E2E_VISUAL_PERTURB_CSS` is a self-test that injects CSS.

Result of two runs:
- 13 of 15 screens match the baseline with 0 differing pixels.
- 02-project-home and 06-screenplay-editor differ.

The cause is timing-dependent view state: the screenplay "Continue" location is saved 2 s after the cursor settles (`ScreenplayView.tsx:182-188`), and the draft layout 0.5 s after it changes (`screenplay/util.ts:97-101`). The fast M0.20 run never saved either; today's slower runs save both.
