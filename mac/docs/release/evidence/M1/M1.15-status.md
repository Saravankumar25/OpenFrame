## Product defects found
1. **PDF pre-flight is quadratic (DoS)**, `crates/openframe-import-export/src/pdf_import.rs:529` (`let dict = &bytes[dict_start.min(i)..i]`), with `dict_start` never reset after a stream (`:567-568`). One top-level `<<` followed by 100k `stream…endstream` blocks (2 MiB) runs for more than 95 s and the watchdog aborts. Reproducer: test `m1_15_pdf_stream_flood_preflight_is_linear`. Planned fix (not applied): set `dict_start = i;` right after `i = end + b"endstream".len();`.
2. **Archive extraction trusts the actual stream, not the declared size**, `crates/openframe-security/src/archive.rs` `extract_all` (cap = `limits`, not `entry.size()`). A lying-header entry that declares 1 KB but inflates to 40 MiB passes `inspect` (the ratio check is skipped below 1 MiB) and is written in full. With PACKAGE limits that allows up to 16 GiB per entry, so disk filling is possible. Corpus: `zip/bomb_lying_header.zip`, `packages/bomb_lying_header.ofstory`. Not yet confirmed by a running test.
3. Suspected, not yet verified: `extract_all` silently overwrites case-colliding names and 8.3 short-name aliases on Windows (`zip/case_collision*.zip`, `zip/short_name_alias.zip`). Packages appear to be protected by the checksums. Duplicate entry names are resolved last-wins.
