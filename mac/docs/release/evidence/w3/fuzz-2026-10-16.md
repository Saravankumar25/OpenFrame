# Windows phase W3 evidence: harden the core (2026-10-16)

Proof level 2 (development computer, ADR-0030). Branch `windows/w1-controls`. Machine: Intel Core Ultra 5, 18 logical
cores, 15.4 GB, Windows 11 Home.

## 1. Fuzzing the parsers that read outside files

Targets (`fuzz/src/lib.rs`): `fdx`, `fountain`, `xml` (the bounded reader under FDX and DOCX), `docx`, `package_archive`
(the zip reader of project, backup and exchange packages: list, read an entry, extract under limits, and nothing written
outside the destination) and `project_manifest` (`openframe.json`).

**How they ran here.** libFuzzer does not link on this Windows MSVC toolchain: the nightly address-sanitizer runtime is
not shipped for MSVC, and without a sanitizer the coverage sections do not resolve with either linker. The same target
functions ran under the seeded mutation driver `fuzz/src/bin/fuzz_drive.rs` (`npm run fuzz -- 300`): no coverage
feedback, random mutations of the corpus (bit flips, inserted, deleted and repeated bytes, splices, truncation), any
panic or any input slower than 5 s fails. The coverage-guided libFuzzer run of the same targets is the CI job `fuzz`
on Linux (60 s per target); it has not run yet because nothing has been pushed.

Seeds: the hostile corpus (`crates/openframe-import-export/tests/fixtures/hostile/`: billion laughs, external entities,
zip slip, zip bombs, lying headers, case collisions, truncated and malformed files), the FDX suite, the screenplay
fixtures and the package fixtures.

The file-based targets (docx, package_archive, project_manifest) run far fewer inputs because each one writes a file
and a folder. A first run found 14 "panics" in package_archive; they were a wrong assertion in the harness
(`extract_all` returns names relative to the destination), not a product fault. The harness now checks that every
name is relative and that nothing appears beside the destination.

## 2. Production `unwrap` and `expect` review

61 calls in production code (test modules, `tests.rs` files and the test-support crate left out), reviewed parsers first.

- **Changed (2):** `AppCore::spawn_task` no longer panics when the system refuses a thread; the task fails with
  "OpenFrame could not start this task. Close other programs and try again." Restoring a recovery state no longer
  panics if the project closed in between; it returns a conflict error.
- **Kept, backed by an invariant (59):** parsers (21): the XML element stack is never empty (it starts with the
  document node and pops only when longer than one); `scene()` creates a scene before `last_mut()`; the Fountain
  continuation lines run only when the last element is of the kind checked just before; regex capture group 0 always
  exists; the PDF column list starts non-empty; the bundled fonts are hash-pinned (a parse failure is a build defect).
  Elsewhere: static regular expressions and compile-time JSON (security redaction, AI commands, themes); map entries
  inserted by the line before (`people.rs`); kind tables that are constants (`documents.rs`); the Arc that always holds
  the core; label sequences without an end (`numbering.rs`); manifests validated before use (`bundle.rs`); a connection
  opened two lines earlier (`indexer.rs`); the Tauri run loop. The fuzz run above exercised every parser path with no
  panic.

## 3. Property tests

`crates/openframe-application/tests/platform/property_invariants.rs` (seeded generator, `OPENFRAME_PROPERTY_CASES=4` gave
four times the seeds): 8 of 8 pass. New in W3: the search index kept up by every edit, undo and redo equals a full
rebuild and passes SQLite's full-text integrity check; an edit whose commit fails (disk full, write failure) leaves the
canonical content, the search index and the undo history exactly as before, and the project reopens with every stored
edit. The plan named the `proptest` crate; the properties extend the existing generator so the repository keeps one way
of writing property tests and gains no dependency.

## 4. Permissions generated from the registry

`platform/permission_matrix.rs`: for every registered operation and every role without its declared capability, the
call is refused with `permission.denied` (checked centrally in `Registry::dispatch` since W3); every read of project
content declares a capability, and the 17 reads that need none are application-level and listed by name. 3 of 3 pass.

## 7. Release hardening (configured, verified in W4)

`scripts/with-msvc-linker.mjs` (every release path: `npm run build`, `bundle`, `perf`) adds control-flow guard and
remaps the repository, Cargo and Rust toolchain folders out of panic text; the release profile strips symbols. The
governance test checks the flags. Today's debug executable still holds 2,271 personal paths
(`scripts/scan-installer.mjs`); W4 runs the scan on the release build, which must show none.
