Highest-risk findings, in order:

1. **C4 (Medium, new):** the asset-protocol scope grants the webview read access to the whole project `cache/`
   folder. That folder holds `cache/intelligence.sqlite` (derived chunks of every member's private notes, filtered
   only at query time), the package-export staging copy of the project database and import staging folders. This
   reopens part of what WEB-02 closed for `project.sqlite`. Nothing in the frontend loads files from `cache/`.
2. **B3 and B4 (GAP):** Control Flow Guard is not enabled, CET compatibility is not set, and no release step
   verifies ASLR, DEP, CFG or the absence of debug data in the shipped executable.
3. **D5 and D6 (PARTIAL and GAP):** the sidecar is assigned to its kill-on-close Job Object after it starts, a failed
   assignment is silent, and there is no orphan sweep at startup. The 2026-09-30 review accepted this as AI-05; the
   permanent standard in section 1a now requires it.
4. **E3 and E4 (PARTIAL):** `confine` checks symlink escape only for paths that already exist, so a write below a
   junctioned folder can leave the root; network-location refusal is syntactic only (mapped network drives and
   junctions or symlinks to UNC targets pass).
5. **F2, F3, F5, F8 (PARTIAL):** the release gates rerun `cargo deny` but not `cargo audit` or `npm audit`; the Store
   job produces no SBOM; GitHub Actions and installed tools are pinned by tag or not at all.

**TF-2. Enable Control Flow Guard (B3).** Add to `.cargo/config.toml`:

```toml
[target.x86_64-pc-windows-msvc]
rustflags = ["-C", "control-flow-guard"]
```

Safe at runtime (small overhead on indirect calls). It changes every crate's build fingerprint, so it forces a full
rebuild: do not apply while another build is running. A `RUSTFLAGS` environment variable would override it; CI sets none.
Needs one release build plus `dumpbin /loadconfig` (Guard CF flags present) to verify.

## 6. Positive observations

- The webview is treated as untrusted end to end: capability file, CSP, `freezePrototype`, no fs, shell or HTTP plugin,
  and file opening by asset id with executable types revealed instead of launched. Rule-based enforcement in
  `scripts/architecture-lint.mjs` turns these into blocking CI checks.
- Path handling covers the Windows-specific traps that many desktop apps miss: device namespaces, `\\?\GLOBALROOT`,
  reserved names including superscript digits and `CONIN$`, alternate data streams and junction resolution for
  protected folders.
- Archive and document parsing is bounded before third-party parsers see the data (central directory pre-check, ratio
  and stream caps, PDF pre-flight on a large-stack thread).
- Model distribution does not rely on TLS: Ed25519 over exact bytes, SHA-256 per artifact, quarantine on mismatch,
  redirect policy per hop, and a release gate that refuses the development key.
- The sidecar runs without a shell, on loopback, with a per-launch key in the environment, stripped `LLAMA_*` overrides
  and no web UI.
- Migrations take a verified safety backup and run in one transaction; received databases are screened for triggers,
  views and hostile identifiers.
