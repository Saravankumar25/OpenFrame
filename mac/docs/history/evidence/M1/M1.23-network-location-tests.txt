Changes
- crates/openframe-security/src/lib.rs
  - drive_kind(letter): GetDriveTypeW (DRIVE_REMOTE = 4). Declared with extern "system" like util.rs and
    distribution.rs, so no Cargo.toml or Cargo.lock change and no new windows-crate feature. One unsafe call with a
    SAFETY comment; file added to UNSAFE_ALLOW in scripts/architecture-lint.mjs with the reason.
  - check_user_path(Refuse) refuses a mapped network drive (project_format.network_location); Allow (dialog-chosen
    import/export files) keeps accepting shares and mapped drives: the deliberate exception, recorded in doc 20 T4a.
  - is_network_location(path): UNC syntax first (no filesystem access), then drive type, then for well-formed local
    paths the nearest existing ancestor is canonicalized and refused if it resolves to a share or mapped drive.
  - validate_output_dir (project parent folders) now rechecks the canonical folder with Refuse (was Allow).
  - The decision is split: check_user_path_with / is_network_location_with take an injected drive classifier.
- crates/openframe-project-format/src/lib.rs is_network_path delegates to is_network_location.
